## Функционал

### Маскирование данных

- `get_mask_card_number` - маскирует номер карты
- `get_mask_account` - маскирует номер счета
- `mask_account_card` - маскирует 0номер карты или счета в зависимости от типа

### Работа с датой и временем
- `get_date` - преобразует строку с датой в формате 'YYYY-MM-DDTHH:MM:SS.ssssss' в формат 'DD.MM.YYYY'

### Работа со словарями

- `filter_by_state` - фильтрует список словарей
- `sort_by_date` - сортирует список словарей по дате

### Работа с массивами транзакций
- `filter_by_currency` - Принимает список транзакций и строку с кодом валюты (например, "USD" или "RUB"). Возвращает генератор, который последовательно выдаёт только те транзакции, где валюта совпадает с указанной.
- `transaction_descriptions` - Получает список транзакций и возвращает генератор, который выдаёт описание каждой транзакции.
- `card_number_generator` - Генерирует номера карт в виде строк с ведущими нулями от числа start до end включительно.
- `convert_to_rub` - Конвертирует сумму транзакции в рубли.
- `load_transactions` - Загружает список транзакций из JSON-файла.


### Фикстуры

- `masks_card_number`- Заготовка маскированного номера карты, используемая в тестах для проверки правильности маскировки.
- `masks_account_number`- Заготовка маскированного номера счета, используемая в тестах.
- `widget_date`- Строковое представление даты 15.04.2023, используемое для проверки функции извлечения даты.
- `sample_data`- Образец данных — список словарей с различными статусами, датами и возможными отбросами полей для тестирования фильтрации и сортировки.
- `sample_transactions` - Возвращает список транзакций.

### Тестирование

#### test_masks.py
- `test_get_mask_card_number`- Убеждается, что функция возвращает ожидаемый маскированный номер карты.
- `test_get_mask_card_number_parametrize`- Проверяет корректность маскировки для различных форматов номера карты, включая с пробелами и ошибочные случаи.
- `test_get_mask_account`- Проверяет, что функция маскирует номера счетов правильно.
- `test_get_mask_account_parametrize`- Проверяет обработку различных вариантов номеров счета, включая неправильные и короткие.

#### test_widget.py
- `test_mask_account_card`- Проверяет, что функция корректно маскирует номера карт и счетов по заданным шаблонам.
- `test_mask_account_card_invalid_input`- Проверяет обработку некорректных входных данных (пустые, None, неправильные типы) для маскировки карты или счета.
- `test_get_date`- Проверяет, что функция правильно извлекает дату из различных строковых форматов.
- `test_get_date_parametrize`- Проверяет, что функция возвращает None для пустых или некорректных дат.

#### test_processing.py
- `test_filter_by_state`- Убеждается, что функция фильтрует данные верно — оставляет только записи со статусом "EXECUTED".
- `test_sort_by_date`- Проверяет, что списки сортируются по дате от самой новой к старой, правильно обрабатывая некорректные или отсутствующие даты.
- `test_ordering_of_sorted_data`- Дополнительная проверка правильности порядка отсортированных данных — что даты идут по убыванию.

#### test_generators.py
- `test_filter_by_currency` - Проверяет правильность фильтрации транзакций по валюте.
- `test_transaction_descriptions` - Проверяет получение описаний транзакций.
- `test_card_number_generator` - Проверяет правильность генерации номеров карт в диапазоне.

#### test_decorators.py

- `successful_function` - Пример функции, складывающей два числа.
- `error_function` - Функция, которая делит x на y. В случае деления на ноль выбрасывает исключение ZeroDivisionError.
- `test_successful_function` - Проверяет правильность результата и наличие соответствующих записей в лог-файле.
- `test_error_function` - Тест, который вызывает error_function с нулем и проверяет, что выбрасывается ZeroDivisionError, а лог содержит информацию об ошибке.

#### test_utils.py

- `test_load_transactions_empty_file` - Проверяет, что функция load_transactions возвращает пустой список, если файл содержит пустой список ([]). Использует мок для файла с пустым массивом.
- `test_load_transactions_valid_file` - Проверяет загрузку корректных данных из файла с одной транзакцией. Убеждается, что возвращенный список содержит одну запись с правильным значением amount.
- `test_load_transactions_invalid_json` - Проверяет сценарий, когда файл содержит некорректный JSON. Функция должна возвращать пустой список в случае ошибки парсинга.
- `test_load_transactions_file_not_exist` - Проверяет поведение функции, когда файл не существует (используется мок, возвращающий False при проверке существования файла). Ожидается возвращение пустого списка.
- `test_load_transactions_not_a_list` - Проверяет случай, когда содержимое файла — это JSON-объект, а не список. Функция должна возвращать пустой список.
- `test_convert_to_rub` - Тестирует функцию convert_to_rub, которая конвертирует USD в рубли, обращаясь к внешнему API. Мок моделирует успешный ответ API с курсом 7500. Проверяет, что результат — правильная сумма в рублях.
